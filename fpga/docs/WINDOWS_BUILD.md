# Windows build steps (official Gowin flow) - written, NOT run

1. Install **Gowin EDA** (GOWIN FPGA Designer, Education edition is enough for GW2AR-18C) from Gowin's site / the Sipeed Tang Nano 20K wiki, and the USB driver the Gowin Programmer installs. Licence setup: follow Gowin's installer; I have not verified it.
2. Copy this whole `fpga` folder somewhere without spaces in the path (e.g. `C:\byteforge\fpga`).
3. Open Gowin EDA -> **File > Open** -> `fpga\gowin\byteforge_tang20k.gprj`. Check **Project > Configuration > Device**: `GW2AR-LV18QN88C8/I7` (series GW2AR, package QFN88).
4. The ROM image `byteforge_rom.hex` is next to the project file. Verilog `$readmemh("byteforge_rom.hex")` is resolved by the synthesis tool; if Gowin reports it cannot open the file, add the hex to the project (File list > Add) or set the `ROM_FILE` parameter in `tang_nano_20k_top.v` to the absolute path with forward slashes. **Check the synthesis report that the program ROM is not all zeros** (an empty ROM would read as opcode 0x0000, not HALT).
5. Double-click **Synthesize**, then **Place & Route**. Open the reports: *Timing Analysis Report* (clock `clk_27M`, target 37.037 ns, must be met), *Resource Utilization* (expect roughly 1.3 k LUT, 0.4 k registers, 16 BSRAM - my numbers come from the open-source flow, not Gowin), and the synthesis log: confirm **no latches** and that both memories became BSRAM.
6. Plug the Tang Nano 20K in by USB-C. Open **Gowin Programmer**, choose the `.fs` from `fpga\gowin\impl\pnr\`, mode **SRAM Program** (volatile) to try it; use *embFlash/External Flash* only after it works.
7. Wiring (3.3 V logic): module DIN->73, CLK->74, **CS->41**, DC->77, **RST->48**, BL->42, GND->GND. **Module VCC comes from the carrier's own regulator, not from the Tang Nano 3V3 rail** (see docs/HARDWARE_POWER.md). Buttons between the FPGA pin and GND: Up 27, Down 28, Left 25, Right 26, A 29, B 30, Reset 31. Keep the board's 40-pin RGB LCD connector and the HDMI port disconnected. Before first power-up read docs/SECTION22_23_CORRECTIONS.md section B (pins 73/74 still carry BL616 HSPI net names).
8. Expected behaviour (from simulation, not seen on hardware): about 0.3 s of panel reset, the panel initialises, a black fill of the 240x320 portrait window (76 800 pixels, roughly 0.2-0.3 s), then the backlight turns on and a cyan 40x40 square appears. A button press recolours the square: Up red, Down green, Left blue, Right yellow, A white, B magenta (one redraw per press; if several buttons are pressed in the same sample, only the first in the order Up, Down, Left, Right, A, B is drawn). LEDs are active low: led_n[1] on = halted, led_n[0] on = fault/overrun. The reset button restarts everything including the panel init.

Alternative, open-source (used here for the numbers): `scripts/build_oss.sh` (needs yosys, nextpnr-himbaechel, apycula). Not tested on Windows.
